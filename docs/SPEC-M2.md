# M2 module spec: model routes, secrets, launcher (Module C)

Decision (operator, 2026-11-13): default model route is **opendesign `deepseek-v4.1-flash`, reasoning `max`**.
Backup routes, selectable in the T3 model picker: **commandcode** (`deepseek/deepseek-v4.1-flash`, thinking: only `high`)
and **opencode-go** (`deepseek-v4.1-flash`, all thinking levels). The opendesign eco model
(`deepseek-v4.1-flash-eco`) offers only `medium`. Automatic provider failover does not exist in dsh (checked
`dsh-llm-retry`, `dsh-llm`, `dsh-llm-pi-ai`); "backup" means available and selectable.

Secrets rule (hard): API key **values** are never printed, logged, written to T3 settings, put in YAML, or passed
through a brief/report. The launcher reads them at process start and passes them to the child only as environment
variables. Reports show names, `set`/`unset`, the source, and at most the value length.

## Why a launcher
T3 starts `commandPath commandArgs...` for each provider instance. Instead of `dsh --profile P-acp`, the instance
runs the bridge: `commandPath: <node absolute path to bin/t3code-bridge-dsh.js or the installed bin>`,
`commandArgs: ["launch", "<profile>"]`. `launch` resolves keys, then execs
`dsh --profile <profile>-acp --patch <routes overlay>` with `stdio: "inherit"` and the resolved env, forwards
SIGTERM/SIGINT, and exits with the child's code. ACP traffic passes through untouched.

## Files
`src/routes.js`
- `DEFAULT_ROUTES` (exported object) and `renderOverlay(routes = DEFAULT_ROUTES)` -> YAML **text** of a dsh patch overlay
  (top-level array): one entry targeting `llm-pi-ai` (`name: "@deepseek-ai/dsh-llm-pi-ai"`) with
  `config.providers` for `opendesign`, `command-code`, `opencode-go`, and one entry targeting `agent-default-model`
  (`name: "@deepseek-ai/dsh-agent-default-model"`, `config: {provider: opendesign, model: deepseek-v4.1-flash, reasoningEffort: max}`).
  Provider/model/compat shapes: copy exactly the shape used in `~/.dsh/profiles/dsbot/cordis.patch.yml` (read only; it holds
  env var *names* only: OPEN_DESIGN_API_KEY, COMMAND_CODE_API_KEY, OPENCODE_GO_API_KEY). Per operator rules:
  opendesign models `deepseek-v4.1-flash` (reasoningEfforts medium/high/max, input text+image) and
  `deepseek-v4.1-flash-eco` (reasoningEfforts: medium only, input text); command-code model `deepseek/deepseek-v4.1-flash`
  (reasoningEfforts: high only); opencode-go model `deepseek-v4.1-flash` (reasoningEfforts low/medium/high/max).
  Deterministic output (stable key order), header comment `# generated by t3code-bridge-dsh; contains env var names only, never keys`.
- `writeOverlay(path, { dryRun })`: atomic write, returns `{ changed }`.
- `overlayPath(env)` -> `<XDG_CONFIG_HOME or ~/.config>/t3code-bridge-dsh/routes.yml`.

`src/secrets.js`
- `SOURCES` table: for each env var name, where to look, in order: (1) the process env; (2) `<DSH_HOME>/.env` (KEY=VALUE lines,
  optional quotes, comments); (3) pi auth `~/.pi/agent/auth.json` (provider `command-code` -> COMMAND_CODE_API_KEY, `opendesign` ->
  OPEN_DESIGN_API_KEY; inspect the JSON structure by printing KEY NAMES ONLY, never values); (4) opencode auth
  `~/.local/share/opencode/auth.json` (provider `opencode-go` -> OPENCODE_GO_API_KEY).
- `resolveKeys({ env, dshHome, piAuthPath, opencodeAuthPath })` -> `{ env: {NAME: value}, report: [{name, state: "set"|"unset", source, length}] }`.
  The returned `env` holds values (only for spawning); `report` never does. Missing/unreadable/invalid files are skipped, not fatal.
- `maskReport(report)` -> string lines for display.

`src/launch.js`
- `buildLaunch({ profile, dshPath, env, dshHome, overlay, ...paths })` -> `{ command: dshPath, args: ["--profile", "<profile>-acp", "--patch", overlay], env, report }`; no spawn.
  Throws if `profile` is empty or not `[a-z0-9][a-z0-9._-]*`.
- `launch(opts)` -> spawns with `stdio: "inherit"`, forwards signals, resolves with the exit code. `findDsh(env)` resolves `dsh` from PATH.
